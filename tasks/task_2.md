# Практическое задание 2: Интерактивная панель управления UI-компонентами

## Описание задания

Создайте веб-приложение — тематический дашборд, которое демонстрирует создание, управление и взаимодействие различных UI-компонентов (виджетов) с использованием принципов ООП.

### Требования к тематике

Тема дашборда должна быть осмысленной и практически применимой. Примеры:

- Дашборд аналитики
- Персональный организатор
- Мониторинг системы
- Игровая статистика
- И другие темы на ваше усмотрение

### Обязательные требования

- Из всех виджетов должно быть **как минимум два**, которые получают данные со сторонних API (материал про API в следующей лекции)
- Весь проект должен быть выгружен на **GitHub** с активным **GitHub Pages**

## Архитектура проекта

Примерные требования к архитектуре и реализации (могут быть изменены на ваше усмотрение):

### Структура файлов

Проект должен быть разбит на модули (ES6 Modules):

```
index.html          - основной файл, подключающий main.js как модуль (type="module")
main.js             - главный файл приложения, отвечающий за инициализацию и общую логику
js/                 - директория для модулей с классами
├── UIComponent.js  - базовый (абстрактный) класс для всех виджетов
├── ToDoWidget.js   - класс виджета "Список дел"
├── QuoteWidget.js  - класс виджета "Случайная цитата"
└── Dashboard.js    - класс, управляющий всей панелью (коллекция виджетов)
styles/             - директория для стилей
├── main.css        - основные стили приложения
└── components.css  - стили для виджетов
```

## Требования к классам

### Базовый класс UIComponent

Должен иметь:

- **Конструктор**, принимающий конфигурацию (например, `title`, `id`)
- **Метод `render()`**, который возвращает DOM-элемент виджета (обертку)
- **Метод `destroy()`**, который корректно удаляет виджет из DOM и очищает слушатели событий
- **Общие методы** для всех виджетов (например, `minimize`, `close`)

### Конкретные классы виджетов (наследуются от UIComponent)

#### ToDoWidget

Реализует функционал из старого задания:

- Добавление задач
- Удаление задач
- Отметка выполненных задач

**Требования:**

- Вся логика должна быть инкапсулирована внутри класса
- Данные списка дел должны храниться как свойство этого класса

#### QuoteWidget

Отображает случайную цитату и кнопку "Обновить".

**Требования:**

- При нажатии цитата меняется
- Цитаты можно хранить в массиве прямо в классе

### Класс Dashboard

**Обязательные методы:**

- `addWidget(widgetType)` — добавляет виджет указанного типа
- `removeWidget(widgetId)` — удаляет виджет по ID

**Функциональность:**

- Инкапсулирует в себе массив (коллекцию) активных виджетов
- Отвечает за отрисовку общей сетки или списка виджетов

### Главный файл main.js

Должен:

- Создавать экземпляр `Dashboard`
- Реализовывать логику кнопок "Добавить виджет ToDo", "Добавить виджет Quote" и т.д., которые вызывают методы дашборда
- Управлять общей структурой страницы

## Функциональные требования

1. **Динамическое добавление и удаление виджетов** разных типов
2. **Независимое состояние** каждого виджета (список задач, текущая цитата)
3. **Корректное удаление слушателей событий** при удалении виджета (используйте `removeEventListener` или делегирование событий)
4. **Чистый, читаемый CSS** (рекомендуется использовать CSS Grid или Flexbox для layout панели)

## Примерный план промптов для нейросети

### 1. Спроектируй структуру проекта

```
Спроектируй файловую структуру для одностраничного приложения на чистом JavaScript (ES6+), используя модули. Проект должен состоять из HTML-файла, главного JS-файла (модуля), папки для классов-компонентов и папки для стилей. Опиши назначение каждого файла.
```

### 2. Создай базовый класс

```
Напиши код на JavaScript для базового (абстрактного) класса UIComponent. Он должен иметь конструктор, принимающий title и id, и методы render() (пока возвращает пустой div) и destroy(). Убедись, что код написан в стиле ES6.
```

### 3. Реализуй конкретный виджет (например, ToDo)

```
Создай класс ToDoWidget, который наследуется от UIComponent. Переопредели метод render(), чтобы он возвращал DOM-элемент с полем ввода, кнопкой 'Добавить' и списком. Внутри класса реализуй методы для добавления и удаления задач, храня массив задач как свойство класса. Не забудь про инкапсуляцию.
```

### 4. Создай класс для управления панелью

```
Напиши класс Dashboard. Он должен хранить массив виджетов. Реализуй методы addWidget(widgetType), который создает экземпляр нужного класса виджета (например, new ToDoWidget(...)), добавляет его в массив и вставляет в DOM, и removeWidget(widgetId), который находит виджет по ID, вызывает его метод destroy() и удаляет из массива.
```

### 5. Собери всё вместе в главном модуле

```
Напиши код для main.js (ES6 module). Импортируй в него все классы виджетов и класс Dashboard. Создай экземпляр Dashboard. Найди в DOM кнопки для добавления виджетов и назначь им обработчики, которые вызывают dashboard.addWidget('todo').
```

### 6. Улучши стилизацию и UX

```
Напиши CSS-код для стилизации панели и виджетов. Используй Grid для расположения виджетов. Добавь стили для кнопок, списков, состояний (например, выполненная задача). Сделай так, чтобы виджеты можно было перетаскивать (опционально, для сложного уровня).
```

### 7. Добавь новый виджет (например, QuoteWidget)

```
Теперь, следуя той же схеме, создай класс QuoteWidget, наследуемый от UIComponent. Реализуй его логику. Покажи, как расширить Dashboard, чтобы он поддерживал этот новый тип виджета, не ломая существующий код. Это демонстрация полиморфизма и открытости/закрытости.
```

## Полезные советы

- Используйте принципы ООП: инкапсуляция, наследование, полиморфизм
- Следуйте принципу единственной ответственности (SRP) — каждый класс должен отвечать за одну вещь
- Обратите внимание на управление памятью — правильно удаляйте слушатели событий
- Используйте современный синтаксис ES6+ (стрелочные функции, деструктуризация, модули)
- Сделайте интерфейс интуитивно понятным и визуально привлекательным
